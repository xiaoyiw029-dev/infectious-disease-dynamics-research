# 文件维护与协作规则

## 阅读入口

先读根目录README和研究决策总档案。需要详细方法时进入对应专题；需要说明旧尝试时查研究过程记录，不以文件修改时间判断方案是否仍有效。

## 修改原则

1. 当前方案只在总档案和对应专题维护；近期任务只在任务清单维护。
2. 数据口径、模型结构、参数边界和验证方案的实质变更由负责人确认。未确认事项明确标为待定。
3. 修改数学内容时同步检查符号、单位、观测定义与实现，不把拟合改善写成机制证明。
4. 原始数据和文献不覆盖；当前结果保留输入版本、代码、配置和评分表。
5. 方案停用后记录设置、关键结果、停用原因及适用限制，再清理重复输出。尚未定论的对照不按废稿删除。
6. 当前文档使用客观研究表述，区分已完成、已确认、待验证，不写期刊目标或承诺性结论。

## 阅读版

Markdown是编辑源，公式用TeX数学定界符。总档案更新后，在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe tools\render_research_record.py
```

生成同目录HTML阅读版。公式使用MathJax渲染，首次加载需网络；离线时可在已配置数学渲染的Markdown预览中阅读。HTML不单独维护。

## 协作与共享

私有仓库仅向已获授权的合作者开放。修改前同步远端，分别使用分支，说明变更内容并经检查后合并；大型原始资料按来源或受控渠道共享，不混入代码提交。Git跟踪与本地目录不是同一状态，本次本地整理不自动提交、推送或调整已有暂存内容。
