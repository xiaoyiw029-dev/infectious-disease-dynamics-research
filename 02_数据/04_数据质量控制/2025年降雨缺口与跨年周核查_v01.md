# 2025 年降雨缺口与跨年周核查

核查日期：2026-10-05。

## 1. 核查范围与结论

本次针对 2025-W43、W52、W53 重新读取 INMET 原始小时记录，保留人口加权州均值及完整 168 小时降雨标准，不执行插补、不改写原始文件、不拟合模型。

W43、W52 的周汇总结果与独立复算一致，未发现这两周由日期归周、数值解析或人口加权造成的差异。降雨覆盖下降确实存在于所下载的原始年度文件中，主要表现为数值字段空白，而非缺测被误解析为零。多个站在相同时刻出现空白，但仅凭年度文件不能判断上游原因是通信中断、设备异常还是数据库导出问题。

W53 所需跨年记录已补入，主候选周表由 156 周扩展为 157 周。现有主候选覆盖 2023-W01 至 2025-W53，包括 2025 年完整的 53 个流行病学周。**日历连续不等于每周空间覆盖合格；W52 的降雨仍不能作为全国输入。**

## 2. 数据来源与独立核对

2025 年资料沿用项目已有的 `2025.zip`。2026 年资料下载自 [INMET 年度历史数据页面](https://portal.inmet.gov.br/dadoshistoricos)所列 [2026 年自动站 ZIP](https://portal.inmet.gov.br/uploads/dadoshistoricos/2026.zip)，页面标示截至 2026-08-31。这里只读取补查目标周所需记录，不把下载整个年度文件解释为已完成 2026 年气候整理。

| 来源 | 文件大小 | 站点 CSV 文件数 | 本轮用途 |
|---|---:|---:|---|
| 2025.zip | 90,898,634 字节 | 594 | 核查 W43、W52，并提取 W53 的 2025 年部分 |
| 2026.zip | 64,189,032 字节 | 639 | 提取 W53 的 2026 年部分 |

新程序独立使用 CSV 字段解析与 `zoneinfo` 时间换算；空白、-9999 标记、不可解析值和超出既定范围的值分别计数。每站按当地星期日零点至下一星期日零点生成预期小时集合，与原始 UTC 时刻核对。跨年周拼接两个年度文件的实际记录，不按年份分别计算后相加周均值。

核查结果：

1. W43、W52 逐站的记录数、三项气候有效小时数及数值和，均与现有站点周表一致。
2. 两周人口加权温度、湿度、完整降雨及覆盖指标均与现有主候选一致。
3. 新表前 156 周逐项保持不变；新增 W53 与数据Y周标签、起止日期一对一匹配。
4. 空白与零值区分、小数逗号与缺测标记、非法值分类、W53 的 168 个唯一时刻四项测试通过。

输入与输出 SHA-256、逐站统计、共同缺测时刻及原始文件行号均已保存。这里的“一致”针对本次选定的两周和既定质量规则，不代表所有年份、所有站点均已获得独立验证。

## 3. W43 与 W52 的缺口

| 指标 | 2025-W43 | 2025-W52 |
|---|---:|---:|
| 有小时记录的站数 | 588 | 594 |
| 预期时刻中缺少整行的站点小时数 | 0 | 0 |
| 雨量字段空白的站点小时数 | 40,417 | 39,459 |
| 雨量为缺测标记、不可解析值或超范围值的小时数 | 0 | 0 |
| 满足完整 168 小时雨量的站数 | 122 | 1 |
| 完整雨量覆盖的 UF 数 | 20 | 1 |
| 完整雨量有效州人口占比 | 79.169% | 1.365% |
| 至少 160 小时有效雨量的站数（仅作对照） | 281 | 332 |
| 160 小时对照覆盖的 UF 数 | 25 | 25 |

空白小时总数同时包含长期缺测站和短时缺测，不能全部归因于少数集中时刻。为识别短时缺口，另检查本周至少有 160 个有效雨量小时的站点：

- W43 的 2025-10-22 20:00 UTC 有 123 个这类站点雨量为空，21:00 UTC 有 112 个。同期全体 588 站中，雨量无效分别为 371、360 站。
- W52 的 2025-12-22 20:00 UTC 有 295 个这类站点雨量为空，2025-12-23 09:00 UTC 有 293 个。同期全体 594 站中，雨量无效分别为 530、531 站，温度、湿度与雨量同时无效分别为 524、526 站。
- 例如巴西利亚 A001 站在 W52 的上述两个时刻，原始文件中的雨量、温度和湿度均为空。该周有 168 条时间记录，但只有 166 个有效雨量值，因而不满足完整 168 小时要求。

W52 唯一满足完整雨量要求的站是 MS 州 A724。其雨量即使可以计算，也不能当作全国平均降雨。不能将 530/594 等站点比例解释为人口覆盖率，也不能仅因温湿度同时空白就断定是某一种设备故障。

160 小时版本能保留更多站点，但保留的是不足整周的已观测雨量和，不能称为已经恢复完整周雨量。本次未改用该版本，也没有按 168/有效小时数进行比例放大。

## 4. W53 的跨年补齐

W53 为 2025-12-28 至 2026-01-03。以巴西利亚时区为例，其小时记录从 2025-12-28 03:00 UTC 开始，最后一个纳入时刻为 2026-01-04 02:00 UTC；各站按各自时区处理，不能只读取 UTC 意义的 1 月 1 日至 3 日。

| W53 指标 | 结果 |
|---|---:|
| 目标周至少有部分记录的站数 | 613 |
| 完整 168 小时雨量的站数 | 253 |
| 完整雨量覆盖 UF 数 | 25 |
| 完整雨量有效州人口占比 | 98.841% |
| 完整雨量未覆盖 UF | RO、RR |
| 人口加权周雨量空间均值 | 34.269 mm/周 |
| 人口加权周平均温度 | 26.157 °C |
| 人口加权周平均相对湿度 | 73.381% |

温度、湿度均覆盖 26 个 UF，有效州人口占比为 99.663%。这些人口占比只说明相关州至少有合格站点，不代表实际人口空间覆盖率。

W53 的站点集合在两个年度文件间发生变化，部分站只有跨年周的一部分记录。审计中记录的 2,666 个缺失预期站点小时包含这类文件覆盖差异，不能直接解释为已运行站点的通信故障。完整雨量筛选要求实际获得整周 168 个有效小时，新加入但不足整周的站不会进入该指标。

## 5. 当前可用范围与下一步

当前可以使用更新后的周表准备开发期验证；原 63 周仍保留完整雨量主候选和覆盖记录。2025 年日历缺周已解决，W43、W52 的空间覆盖问题尚未解决。程序没有将这些周删除，没有修改其数据Y，也没有生成已确定的训练/验证标签。

建议保持已确认的 168 小时主候选，先在原 63 周开展开发期滚动验证。第一训练段 30 周、预测未来第 1、2、4 周仍是待确认方案。2025 年验证前，应先决定是否进一步获取官方原始补充记录，或者比较其他气候来源及缺失处理方案。没有可核实的补充观测时，不把统计填补包装成真实测量。

若后续接受不足 168 小时的雨量，需重新明确其观测含义，并对全部相关周采用一致规则，不只针对误差较大的周调整。若排除覆盖不足的周，应事先规定标准，同时检查其对后续滞后气候输入的影响，不能看模型评分后再删周。
